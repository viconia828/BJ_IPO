# 申购账户分布公告约束反推方案

> 设计日期：2026-07-11

## 一、问题

现有账户池构建器把两类含义不同的数据按 `lot_level` 直接拼接：

- `subscription_ladder_labels.csv` 提供真实或人工核验的申购金额门槛；
- `allocation_fit_json` 的 `compressed_extra_lots` 提供一个仅用于满足获配户数、获配手数总量方程的压缩解。

压缩解不是账户资金分布。乔路铭样本中，压缩解把 450000 手表示为
31342 户获配 12 手、1 户获配 6 手、73890 户获配 1 手。旧构建器因此把
`2+0=586 万元` 错配为 `31343 户`，并把这一断崖覆盖到后续账户池曲线。

## 二、数据边界

主账户池只使用以下数据：

1. 发行结果公告中的网上获配户数，作为第一获配层累计账户数的硬锚。
2. 发行结果公告中的网上获配手数，作为各获配层累计账户数之和的硬约束。
3. `subscription_ladder_labels.csv` 中经过核验的统计门槛，作为账户曲线的金额切点。
4. 更早样本已经形成的账户曲线，作为新样本层级分布的形状先验。

雪球作者给出的账户区间、资金量拆分和门槛预测只能用于结果印证、异常诊断和人工补录线索，
不能自动写入主账户池，也不能替代公告汇总数据或人工核验梯度。

## 三、反推方法

对每个按申购日期排序的样本：

1. 解析人工梯度，得到 `总获配手数层级 -> 申购金额门槛`。
2. 以公告网上获配户数固定第一层累计账户数 `A1`。
3. 以公告网上发行手数固定累计层级面积：`sum(Ak) = online_lots_total`。
4. 在新样本各层门槛上读取上一只样本完成后累计形成的完整账户快照；快照从第一个本地样本开始逐只新增和细化切点，并为每个切点保留偏差带。
5. 在偏差带内求解第二层及以上账户数并施加 `A1 >= A2 >= ... >= 0` 约束，直到满足公告总手数；偏差带不足时优先放宽高手数尾部。
6. 只把人工梯度对应的门槛写成新观测切点；为满足总手数而补出的隐含层级只参与约束，不直接成为账户池观测。
7. 将本样本新切点叠加到历史状态；两个新门槛之间已有的旧切点按新样本两端插值细化，再执行单调约束，形成下一期账户曲线。
8. 每处理一个样本就固化一个当时可见的账户池快照；正式预测查询目标日期之前的最新快照，历史调参按样本日期查询对应历史快照，禁止读取未来样本。

`--mode account-pool` 可以同时展示近期快照的平滑统计和最新累计快照值，用于诊断稳定性；正式门槛计算仍使用目标日期之前的最新累计快照，不把多个版本再次平均。

累计形式与直接分桶方程完全等价。若 `xk` 表示最终获配 `k` 手的账户数，则：

- `sum(xk) = online_allocated_accounts`
- `sum(k * xk) = online_lots_total`
- `Ak = sum(xj, j >= k)`
- 因而 `A1 = online_allocated_accounts` 且 `sum(Ak) = online_lots_total`

偏差由切点历次更新差异、上一版偏差和最低相对误差共同确定。约束投影优先保留低获配层的历史账户锚；
当历史曲线累计手数高于公告总手数时，调整逐层向高手数尾部增强，避免为了满足总量而把 1 手、2 手附近
样本最充分的账户数一起等比例压低。

如果不存在可用的历史曲线，使用满足公告总量的中性非递增形状作为冷启动；该结果标记为公告约束推断，
不伪装成直接观测。

## 四、禁止事项

- 不再把 `compressed_extra_lots` 或 `residual_extra_lots` 的账户数写入主账户池。
- 不再因为人工门槛覆盖了压缩桶金额，就把压缩桶账户数标记为 `manual_ladder+allocation_fit`。
- 不从雪球正文自动抽取账户区间并写入 `account_pool_history_thresholds.csv`。
- 不改变申购资金总量预测、公告解析和雪球首日估值学习的既有边界。

## 五、验收

- 乔路铭 586 万元切点不再等于压缩解的 31343 户。
- 每个可用样本的第一层账户数等于公告获配户数。
- 完整隐含层级的累计账户数之和等于公告网上获配手数。
- 账户数随申购金额单调不增。
- 920176 重新生成后不再由乔路铭压缩桶制造 577-586 万元断崖。
- 账户池构建、申购预测和调参相关回归测试通过。
