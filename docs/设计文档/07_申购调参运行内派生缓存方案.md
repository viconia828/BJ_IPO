# 申购调参运行内派生缓存方案

## 一、背景

申购资金自动调参已经有离线样本缓存：`subscription_history_sample.csv`、`subscription_ladder_labels.csv`、`account_pool_history_thresholds.csv` 等文件会在调参前统一同步和复用。

本次性能排查发现，慢点不在公告解析或样本同步，而在单次调参运行内反复计算 account-pool 碎股门槛：

- 默认主网格计划约 166 组候选，另有 account-pool prior 分支。
- 每组候选会回放 39 个可评估样本。
- 每个样本预测会重复加载 account-pool 阈值表、解析阈值列、扫描历史行和阈值切点。
- 小规模实测中，10 个候选耗时约 239 秒，其中 `_estimate_account_pool_fractional_cutoff()` 占约 238.7 秒。

已有缓存是文件级缓存，缺少调参热路径里的派生索引缓存。

## 二、目标

本阶段只做运行内缓存和索引化，不改变模型口径：

- 单次调参运行内只读取一次 account-pool 阈值表。
- 将阈值列、排序后的样本行、每行可用插值点预先派生为索引。
- `_estimate_account_pool_accounts_ge()` 优先走索引和查询 memo，避免每次排序、扫列、扫行。
- `tools/tune_subscription_prediction.py` 在进入候选搜索前预加载 account-pool rows，并注入参数字典供所有候选复用。
- 缓存仅驻留内存，不写入新的数据文件。

## 三、不做事项

- 不缓存最终 `build_subscription_prediction()` 结果，因为候选参数会改变申购倍数、配售比例、正股门槛和碎股 cutoff。
- 不跨进程或跨运行复用派生缓存。
- 不改变 `account_pool_history_thresholds.csv` 的文件格式。
- 不改变 cutoff、插值、最新 calibrated snapshot 优先等业务规则。

## 四、缓存边界

缓存对象分三层：

1. `account_pool_rows`
   - 来源：`subscription_prediction_account_pool_rows` 或默认 CSV。
   - 在调参入口预加载一次，放入 base params。

2. `account_pool_index`
   - 从 rows 派生。
   - 包含：
     - `thresholds`：所有有效金额切点。
     - `sorted_rows`：按申购日期和代码排序的行。
     - `row_points`：每行可用 `(threshold, accounts)` 插值点。
     - `has_values`、`has_calibrated`、`is_snapshot` 等布尔标记。

3. `accounts_ge_memo`
   - `_estimate_account_pool_accounts_ge()` 的查询 memo。
   - key 包含金额、顶格金额、recent_samples、half_life 和索引签名。
   - value 是当前函数返回的估算结果副本。

## 五、失效规则

运行内缓存挂在本次 `settings` 字典上：

- 如果 `subscription_prediction_account_pool_rows` 是列表，则索引签名使用该列表对象的 `id()`、长度和首尾代码/日期。
- 如果从默认路径读取，则索引签名使用绝对路径、文件 mtime、size。
- 调参前统一同步若刷新了阈值表，预加载发生在同步之后，因此本轮使用最新文件。
- 不在模块全局持久化业务结果，避免跨任务串数据。

## 六、实现步骤

1. 在 `code/subscription_predictor.py` 新增运行内索引构建函数：
   - `_account_pool_runtime_cache(settings)`
   - `_prepare_account_pool_index(settings)`
   - `_indexed_row_estimate_accounts_ge(indexed_row, amount_wan)`

2. 改造 `_estimate_account_pool_accounts_ge()`：
   - 优先读取 `account_pool_index`。
   - 保留原有优先级：顶格以上为 0、latest calibrated snapshot、latest snapshot、recent weighted median。
   - 对查询结果做 memo。

3. 改造 `_estimate_account_pool_fractional_cutoff()`：
   - 使用缓存索引的 rows、thresholds、source。
   - 保持现有全切点 cutoff 逻辑，先不改成二分，降低行为变化风险。

4. 在 `tools/tune_subscription_prediction.py` 增加预加载：
   - 调参入口读取 history 后，预加载 account-pool rows。
   - `evaluate_subscription_prediction()` 为每个候选复制参数时继承 rows，但不共享候选可变输出。

5. 增加测试：
   - 验证有预加载 rows 时不再重复读 CSV。
   - 验证 account-pool cutoff 结果与旧测试一致。
   - 用 `--max-candidates 1` 或直接函数调用做 smoke，确认候选评估可完成且结果结构不变。

## 七、验收标准

- `tests/validate_subscription_predictor.py` 通过。
- `tests/validate_subscription_prediction_tuning.py` 通过或至少完成核心 smoke。
- 10 个候选的性能剖面中，`_load_account_pool_rows()` 调用数显著下降，`_estimate_account_pool_accounts_ge()` 单次平均耗时明显下降。
- 自动调参输出的候选指标字段保持兼容。
