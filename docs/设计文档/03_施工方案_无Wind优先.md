# 北交所新股估值项目施工方案（无 Wind 优先）

版本：v1.0  
日期：2026-04-14  
状态：待执行

## 一、目标

先把项目主干搭成一个可运行、可迭代、可出报告的版本，再把 Wind 作为后续增强模块单独接回。

本阶段的核心目标不是一次性完成全部功能，而是优先得到一个稳定的正式工程结构：

- 输入新股代码
- 读取策略参数
- 通过东方财富接口获取基础数据
- 在不依赖 Wind 的前提下完成方法二估值
- 输出 Markdown 报告

## 二、当前约束

- 2026-04-14 用户已明确要求：先暂停 Wind 接口相关工作
- 后续编码过程中不做 Wind 实际接入验证
- 可以保留 `wind_helper.py` 或相关参数位，但仅作为占位，不参与当前阶段主流程
- 当前仓库已有大量验证脚本，但尚未整理成正式模块化工程

## 三、总体策略

采用“主干先通、依赖后补”的顺序推进：

1. 先固定正式项目骨架
2. 先做不依赖 Wind 的基础模块
3. 先做能生成报告的最小可运行版本
4. 再补 PDF 解析和本地分时 CSV 增强
5. 最后再单独恢复 Wind

## 四、分阶段实施

### 阶段 1：整理项目骨架

目标：

- 建立正式模块文件
- 建立标准目录
- 保存参数模板和使用文档

计划创建或整理的文件：

- `bse_ipo_valuation.py`
- `config_loader.py`
- `data_fetcher.py`
- `valuation_engine.py`
- `report_generator.py`
- `pdf_parser.py`
- `industry_mapping.py`
- `trend_scorer.py`
- `wind_helper.py`（仅占位，不接入）
- `策略参数.txt`
- `说明文档.md`

计划创建的目录：

- `公告文件`
- `输出`
- `data`

完成标志：

- 仓库目录结构与方案文档一致
- 后续开发不再依赖零散实验脚本作为主入口

### 阶段 2：实现基础层

目标：

- 把配置、行业映射、数据抓取做成稳定接口

优先实现模块：

- `config_loader.py`
- `industry_mapping.py`
- `data_fetcher.py`

具体内容：

- `config_loader.py`
  负责解析 `策略参数.txt`
- `industry_mapping.py`
  负责从参数映射表得到开源一级/二级行业
- `data_fetcher.py`
  负责封装东方财富 API，提供单股查询与近期样本查询

完成标志：

- 传入一个股票代码后，可以稳定返回标准化的新股基础信息
- 可以返回近几个月北交所新股样本列表

### 阶段 3：跑通无 Wind 主流程

目标：

- 在没有 Wind 的情况下，先完成一次完整报告输出

优先实现模块：

- `valuation_engine.py`
- `report_generator.py`
- `bse_ipo_valuation.py`

主流程策略：

- 方法一可比公司估值法允许暂时缺席
- 方法二行业折溢价法先作为主估值方法
- 报告中明确写出当前版本不依赖 Wind

完成标志：

- 输入代码后可以生成 Markdown 报告
- 即使没有 PDF、没有可比公司、没有 Wind，流程也不会中断

### 阶段 4：补 PDF 与本地分时走势能力

目标：

- 利用现有本地资料增强报告完整度

优先实现模块：

- `pdf_parser.py`
- `trend_scorer.py`

本阶段只做以下内容：

- 从 `公告文件` 读取 PDF 并做优雅降级
- 从 `首日分时走势` 本地 CSV 读取 1 分钟数据
- 先实现不依赖 Wind WSI 的走势评分版本

完成标志：

- 有 PDF 时能提取老股转让、公司简介、可比公司
- 有本地 CSV 时能生成走势因子

### 阶段 5：恢复 Wind

目标：

- 把可比公司估值和后续增强功能接回主流程

后续再做：

- `wind_helper.py` 真正实现
- `auto / api_only / excel_only` 通道逻辑
- Wind 失败时的降级与提示

完成标志：

- 方法一恢复完整
- Wind 不可用时主流程仍可继续
