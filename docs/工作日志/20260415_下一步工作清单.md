# 北交所新股估值项目下一步工作 List

创建日期：2026-04-15  
适用场景：下一轮继续推进 PDF 提取优化与主流程剩余大块时直接照单执行

## 一、PDF 提取模块优化

先补一个可复用的“全样本扫描脚本”或扫描入口，批量跑 `公告文件` 下全部 PDF，并输出三条链路结果：

- `extract_old_shares_result()`
- `extract_comparable_companies()`
- `extract_business_desc()`

扫描完成后，按以下四类整理样本结果：

- 提取成功
- 提取失败
- 误提取
- 漏提取

重点观察残余问题是否仍集中在：

- 章节锚点不稳
- 停止锚点过宽或过窄
- 表格行识别变体
- 业务句噪声过滤不足

本轮继续遵守以下约束：

- 优先只改 `pdf_parser.py`
- 优先补章节锚点、停止锚点、表格识别和噪声过滤
- 不扩展与 PDF 提取无关的模块
- 不把 `PB` 作为当前阻塞项
- 不把 Wind 重新设为主流程硬依赖

每轮最小修正后，先跑本地验证脚本：

- `validate_pdf_old_shares_goldens.py`
- `validate_pdf_content_goldens.py`

若复扫后确认有新样本已经稳定，再补进现有黄金样本脚本或新增同类本地验证脚本。

## 二、方法一数据源与估值链路收口

除 PDF 提取外，主流程里还要继续收口的方法一相关大块包括：

- 继续确认 `Wind 原料字段 -> 本地计算` 这条链路在当前口径下稳定可复用
- 继续确认东方财富快照作为主备选源时，`价格 / PE_TTM / 总市值 / 总股本 / EPS_TTM` 的口径说明足够清楚
- 继续确认本地文件数据库、缓存优先、请求台账和 quota 控制在重复运行时都按预期工作
- 如有新的差异样本，优先做“小样本交叉验证”，不要直接扩大到大范围联网扫描
- `PB` 继续保留为后续扩展项，不作为当前主流程阻塞点

## 三、主流程最小回归

当 PDF 提取或方法一链路修正已经影响最终输出时，再选 1 到 2 个样本做最小主流程回归，重点检查：

- 首日流通老股
- 可比公司估值表
- 公司简介
- 方法一目标价
- 综合估值
- 提示文案

主流程回归时，优先选：

- 一个上市公告书 `old_shares` 规则命中明显的样本
- 一个可比公司和公司简介都依赖招股文件提取的样本

## 四、报告展示与提示文案完善

主流程里除“能跑通”之外，仍有一块需要继续完善的是报告展示：

- 评估是否在报告中展示方法二实际采用的历史样本代码
- 评估是否更明确展示时间衰减加权口径与样本范围
- 视样本情况决定是否单独提示“上市公告书未识别，已回退招股文件”
- 持续检查报告中的数据源说明是否和当前真实链路一致，避免文案滞后于实现

## 五、性能与稳定性观察

主流程剩余的大块里，还需要继续盯住稳定性问题：

- 若再次出现单票运行超时，优先检查 PDF 是否被重复完整解析
- 继续确认文本缓存、文件选择和重复调用链路没有被后续改动破坏
- 继续坚持“小范围验证优先”，避免为了排查局部问题做大范围联网回归

## 六、验证资产与脚本沉淀

除了修规则本身，还需要把验证资产沉淀下来，避免每次重新人工排查：

- 补一个可复用的全样本扫描脚本
- 按残余失败模式补新的本地黄金样本
- 若后续主流程回归也逐步稳定，可再考虑补一个最小主流程回归脚本或固定回归入口

## 七、结束前要补记的内容

完成一轮扫描、一轮规则修正或一轮主流程回归后，把以下内容继续补记到当日日志：

- 全样本扫描结论
- 失败模式分类
- 最终修正规则
- 本地验证结果
- 主流程最小回归结果
- 当前仍未完成的大块与下一轮接续点
