# 2026-06-09 工作日志

## 一、920083 招股说明书解析问题修复

本轮针对 `920083` 金戈新材实跑报告中暴露的两个招股说明书解析问题做了修复：

- 公司简介锚点定位正确，但断句候选被同行业可比公司表中的“天马新材主营业务...”句子抢占，导致报告展示的公司简介串段错乱
- 招股说明书 `1-1-135` 页披露了同行业可比公司，但文本中主要是公司名称，缺少紧邻证券代码，原解析器无法形成可比公司代码列表

## 二、公司简介抽取修复

本轮调整了 `code/pdf_parser.py` 中主营业务描述的候选选择逻辑：

- 不再在第一个章节候选命中后立即返回，而是收集发行人主营业务章节、主营业务章节、发行人基本情况章节和全文候选后统一打分
- 对命中已知可比公司名称的候选句降权，避免同行业可比公司对比表里的业务描述覆盖发行人自身简介
- 为 `发行人主营业务情况` 增加更精确的优先章节，减少被目录或后续销售情况章节干扰的概率

`920083` 当前可抽取到的简介为：

> 公司是一家专业研发、生产、销售功能性材料的高新技术企业，也是国家级专精特新小巨人、广东省制造业单项冠军企业，拥有广东省导热高分子材料工程技术研究中心和省级企业技术中心。

## 三、同行业可比公司提取修复

本轮补强了“只披露可比公司名称、不披露证券代码”的解析路径：

- 新增对 `公司选取...作为同行业可比公司` 句式的名称抽取
- 避免误命中 `发行人选取可比公司时...` 这类解释性句子
- 对名称列表中的空格、顿号、逗号、`及/和/与` 等分隔形式做清洗和去重
- 补充本地名称到代码映射：

  - `天马新材` -> `920971.BJ`
  - `联瑞新材` -> `688300.SH`
  - `百图股份` -> `875029.NQ`

## 四、解析缓存版本处理

此前 `business_desc` 和 `comparable_companies` 没有纳入 parser version，旧的错误缓存会持续复用。

本轮已将这两个解析项加入 `PARSE_CACHE_KIND_VERSIONS`：

- `business_desc = 2`
- `comparable_companies = 2`

后续重新运行时，旧版本缓存会自动失效并按新规则重算。

## 五、A/B 机验证口径

本项目当前采用 A/B 机运行：

- A 机：Codex 自带 Python 环境，内置 `pypdf`
- B 机：系统 Python，正式 bat 运行需要在沙盒外提权执行

本轮按两个口径分别验证：

- A 机口径：Codex 自带 Python 可读取真实 `920083` 招股书，并返回正确简介和 5 个可比代码
- B 机口径：沙盒外系统 Python 确认可用 `pypdf`，也可读取真实 `920083` 招股书，并返回一致结果
- 最终正式入口验证时将 `PARSE_CACHE_DIR` 临时改到系统临时目录，避免污染项目内现有 PDF 解析缓存
