# 北交所新股估值项目工作日志

日期：2026-05-12
记录人：Codex
目标：修复 `920220` 在东方财富/Tushare 目标新股字段缺失时无法继续生成报告的问题，增强北交所官网公告接口的超时与临时网络异常处理，并补齐报告一览中的发行价字段。

## 一、问题背景

用户运行 `920220` 时，程序在读取公告和整理估值数据阶段失败，终端显示：

- `运行失败：The read operation timed out`

进一步排查后确认：

- `920220` 当前在北交所官网“公开发行一览”路径已经能查到，简称为 `朗信电气`，发行前代码为 `874326`。
- 北交所公开发行一览中已发布 `2026-05-11` 的招股说明书。
- `920220` 尚未能通过北交所“已上市公司详情”路径稳定查询，因此上市公司公告路径会返回结构异常或未命中。
- 当前项目主流程默认走 Tushare 数据源；当 Tushare 目标 IPO 核心字段缺失时，会尝试东方财富补充。
- 东方财富对 `920220` 可以返回部分展示字段，但发行价、发行 PE、发行总量、申购日等关键字段为空，导致报告能生成但一览关键字段为空。
- 北交所官网接口偶发 `read timed out`、SSL EOF 等临时网络错误时，原 `_fetch_text_once()` 没有统一包装和重试，容易把底层英文异常直接抛到用户界面。

## 二、本次修复

本次修复分三条线完成：

1. 北交所官网接口稳定性
   - `BSEOfficialClient._fetch_text_once()` 增加 3 次短重试。
   - 将 `TimeoutError`、`IncompleteRead`、`OSError`、SSL EOF 等网络异常统一包装为 `BSEOfficialError`。
   - 用户侧不再直接看到 `The read operation timed out` 这类裸英文底层异常。

2. 北交所公开发行一览基础数据兜底
   - 新增 `BSEOfficialClient.build_newshare_ipo_info_by_post_listing_code()`。
   - 从公开发行一览详情的 `newShare` 字段提取：
     - `SECURITY_CODE`
     - `SECURITY_NAME_ABBR`
     - `PRE_LISTING_CODE`
     - `APPLY_DATE`
     - `ISSUE_RESULT_DATE`
     - `ISSUE_PRICE`
     - `AFTER_ISSUE_PE`
     - `TOTAL_ISSUE_NUM`
   - `initialIssueAmount` 按“股”转为“万股”，与项目现有 `TOTAL_ISSUE_NUM` 口径一致。

3. IPO 数据主流程兜底
   - `ipo_data_helper` 的东方财富路径在目标新股完全查不到时，会改用北交所公开发行一览数据。
   - `tushare_ipo_helper` 在 Tushare 未取到目标核心字段、且东方财富补充字段为空时，会继续用北交所公开发行一览补齐缺失字段。
   - 若东方财富提供了主营业务等展示字段，北交所只补缺失的发行核心字段，保留东方财富已有补充信息。

4. 报告一览字段补齐
   - `_一览.txt` 新增 `发行价` 行。
   - 字段顺序调整为：`市盈率`、`发行价`、`最大申购上限（万元）`。
   - 回归测试同步更新，避免后续误删该行。

## 五、当前结论

后续遇到类似 `920220` 这种“官网公开发行一览已出公告，但东方财富/Tushare 目标新股字段未完整同步”的样本，主流程会优先保留既有数据源结果，并自动用北交所公开发行一览补齐发行核心字段。

上市公告书未发布或未命中时，报告仍会按“无上市公告书”方式继续生成；老股转让数据会保持待确认提示，不再影响招股书和基础估值数据链路。
