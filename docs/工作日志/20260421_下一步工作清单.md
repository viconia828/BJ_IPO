# 北交所新股估值项目下一步工作清单
创建日期：2026-04-21  
适用场景：在 `quick_method2_core_only` 已追加边界流通盘样本观察，并初步拆出“阈值问题”和“小盘溢价问题”后，作为下一轮工作的执行清单。

## 零、明日主线任务：调参模块增加手动用户调参出入口

今天主程序侧的公告探测、自动下载与报告生成口径已经阶段性收口，明天最值得推进的新任务，不再是继续追主程序细节，而是给调参模块补一个面向用户的“手动调参出入口”。

### 建议做法

1. 先梳理当前调参链路里哪些入口适合暴露给用户
   重点看 `code/param_tuning.py`、`tools/tune_params.py`、现有各类 `observe_*.py` 工具之间的职责边界。
2. 设计一个轻量的手动入口
   至少支持用户手动指定参数名、候选值或候选组，并明确作用口径是“离线调参”还是“replay 观察”。
3. 输出结果保持和现有调参产物兼容
   尽量继续复用当前的 `.json / .md` 输出结构，避免新入口和旧链路各自生成一套不一致格式。
4. 加最少一条自检或回归
   确保手动入口不会影响现有批量调参阶段。

### 完成标准

- 用户可以不改代码，直接从命令行手动指定一组待验证参数并执行
- 结果能稳定落到现有调参或观察输出目录
- README 补充用法说明
- 至少有一条针对新入口的验证

## 一、当前阶段统一判断

截至 2026-04-21 当前时点，已经形成的新判断是：

- `quick_method2_core_only` 合并 `12` 只有效样本后，整体仍优于旧 baseline
- `price_range_width = 0.12` 的区间命中改善信号更稳
- `float_size_threshold = 1500` 在 `1500 ~ 2000` 万股边界样本上的支持度明显增强
- `small_cap_premium = 0.15` 已完成拆分验证
- 在真小盘样本上，`0.15` 相比 `0.10` 的特征是“区间更强、点估值更激进”
- 默认参数已正式回退为 `small_cap_premium = 0.10`
- `pe_low_threshold = 0.20` 已完成定向调参与 replay 观察，并正式吸收
- 当前还不适合把“整组 core_only 参数已全部验证完成”写得过满

因此当前最合理的主线，不再是继续无差别补样，而是把最后尚未收口的问题拆开验证。

## 二、第一优先级：PE 组剩余问题降为低优先级观察

`small_cap_premium` 与低 PE 阈值这两条线今天都已收口。PE 组剩余未完成的，只剩高 PE 压制相关参数，但当前证据明显不足。

### 建议做法

1. 若后面继续补 PE 观察，只保留为低优先级跟踪  
   重点等真实出现会触发高 PE 压制的样本，再决定是否重开这条线
2. 当前不建议继续动：
   - `pe_high_threshold`
   - `pe_premium_drag`
3. 当前也不建议重新打开：
   - `pe_low_threshold`
   - `pe_discount_boost`
   因为低 PE 这一侧已经形成足够清楚的方向

### 完成标准

- 只有在出现新的高 PE 触发样本后，才重新判断是否值得继续优化高 PE 压制侧

## 三、第二优先级：保留 `1500` 阈值主判断，不再回头做大范围怀疑

截至今天，`1500 ~ 2000` 万股边界组已经给出更一致的方向：

- `5` 只样本里 `4` 只优于 baseline
- 平均绝对误差和区间命中率都向候选方向改善

因此后续处理原则应调整为：

- 不再把 `float_size_threshold = 1500` 当成“完全未定”的问题
- 除非后面出现新的强反例，否则先按“更接近正式固化”处理
- 后续若再补边界样本，只作为加固证据，不作为重新推翻主判断的前提

## 四、第三优先级：把 `price_range_width = 0.12` 视作更稳的组成项

当前已有证据表明：

- 在不触发小盘溢价的样本里，`price_range_width = 0.12` 没有把点估值推偏
- 它对区间命中改善更稳定

因此后续处理原则是：

- 优先把 `price_range_width = 0.12` 视作当前组合中最稳的一项
- 后面若需要继续拆分候选，优先保持它不动

## 五、当前不建议优先做的事

- 不要重新回头开整组 `quick_method2_core_only` 的大范围调参
- 不要把 `small_cap_premium = 0.15` 的争议，误判成 `1500` 阈值本身不成立
- 不要在高 PE 压制样本几乎未触发时，就继续优先调 `pe_high_threshold / pe_premium_drag`
- 不要把已经吸收完成的 `pe_low_threshold = 0.20` 又重新拉回大范围搜索
- 不要因为 `920086` 当前不可用，就停住这条主线
- 不要重新切回 `trend_balance` 或 `WSI` 作为当前第一优先级
- 不要现在就把 `0.15` 直接写死成唯一默认答案

## 六、一句话结论

下一步真正该做的，不是再回头动已经收口的 `quick_method2` 核心参数，而是把高 PE 压制侧降为低优先级观察；如果没有新的高 PE 触发样本，主线就该切回更值得推进的新任务。
