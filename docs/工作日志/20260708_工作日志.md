# 2026-07-08 工作日志

## 920136 真实申购梯度未进入报告修复

用户反馈刚生成的 `920136` 报告中，本地梯度表已经有真实梯度，但报告仍展示估算梯度，没有用真实值替换。

排查结论：

- `data/offline_tuning/subscription_ladder_labels.csv` 中 `920136` 已有手工真实梯度：`1+1=1131.3;2+1=1217.8`。
- `subscription_history_sample.csv` 中 `920136` 也已有发行结果公告解析出的有效申购股数、获配户数等真实申购字段。
- 正式报告生成链路此前只把申购 history 覆盖到 `recent_ipos` 历史样本，没有把目标票 `ipo_info` 本身覆盖一遍；因此目标票报告仍可能使用当次接口/PDF字段缺失后的估算分支。
- `subscription_predictor` 也没有在运行时接收并覆盖手工梯度分档，导致即使本地标签存在，也不会替换 `lot_thresholds` 中的估算门槛。

本轮修复：

- 在 `code/bse_ipo_valuation.py` 中新增目标票申购 history overlay：正式生成报告前，使用本地 `subscription_history_sample.csv` 为目标票补齐真实申购字段。
- 同文件新增本地手工梯度 overlay：从 `subscription_ladder_labels.csv` 读取目标票 `manual_ladder`，写入 `SUBSCRIPTION_MANUAL_LADDER`，供申购预测器使用。
- 在 `code/subscription_predictor.py` 中新增运行时手工梯度解析与覆盖逻辑：
  - 优先用手工梯度识别碎股门槛；
  - 用 `manual_ladder` 覆盖同名 `1+1`、`2+1` 等分档；
  - 覆盖后重新计算 `display`，避免报告继续展示被真实分档压低后的估算分档。
- 新增回归：
  - `tests/validate_subscription_predictor.py` 覆盖 `920136` 手工梯度运行时覆盖；
  - `tests/validate_main_flow_regression.py` 覆盖目标票 history/梯度 overlay，并确认不会误覆盖目标票已有上市日期。

验证：

- `python -X utf8 tests\validate_subscription_predictor.py`
- `python -X utf8 tests\validate_main_flow_regression.py`
- `python -X utf8 -m py_compile code\subscription_predictor.py code\bse_ipo_valuation.py tests\validate_subscription_predictor.py tests\validate_main_flow_regression.py`
- 直接用本地 `920136` 数据调用 overlay + 预测，确认 `1+1=1131.3`、`2+1=1217.8` 均命中，来源为 `manual_ladder`。
