## 九、继续推进：大户资金池参考

用户提出新的建模方向：近期获配情况可以用来估计打新市场上资金体量在某个金额以上的大户约有多少户；这类大户群体相对稳定，不会轻易大幅波动，通常应平滑渐变。

本轮先把这个方向做成观察入口，暂不并入正式预测模型。

新增：

- `tools\tune_subscription_prediction.py --mode account-pool`
- 参数：
  - `--account-pool-thresholds`
  - `--account-pool-recent-samples`
  - `--account-pool-half-life`

当前做法：

- 读取 `allocation_fit_json` 中的获配分桶。
- 对每个申购金额阈值，累计阈值以上分桶的账户数。
- 用 `allocation_fit_confidence` 与样本半衰期做平滑加权。
- `top_apply_below_guaranteed=true` 样本标为时间优先下限，因为公告只确认顶格账户抢时间，不能确认所有顶格申购账户总数。

默认命令：

- `python tools\tune_subscription_prediction.py --mode account-pool`

最近 12 个样本默认阈值输出：

- `>=300` 万：平滑约 76931 户，中位数 73447 户
- `>=500` 万：平滑约 58568 户，中位数 58838 户
- `>=800` 万：平滑约 43250 户，中位数 46264 户
- `>=1000` 万：平滑约 34784 户，中位数 38946 户
- `>=1500` 万：平滑约 7547 户，中位数 0 户
- `>=2000` 万：平滑约 2600 户，中位数 0 户

注意：

- 这些数字不是公告直接披露的真实资产账户数，而是由获配分桶和当前 `allocation_fit` 反推的参考值。
- 对较高阈值，最新样本若顶格申购金额低于阈值，会出现最新样本为 0 户，但平滑值仍由更早样本贡献。
- 下一步更适合把这组平滑参考作为“市场资金池先验”，用于约束有效申购倍数或顶格不足正股分类，而不是直接替代当前倍数模型。

新增验证：

- `python -m py_compile tools\tune_subscription_prediction.py tests\validate_subscription_prediction_tuning.py`
- `python tests\validate_subscription_prediction_tuning.py`

## 十、继续推进：大户资金池 prior 离线检查

本轮把上一轮的 `account-pool` 观察入口向模型约束推进了一步，但仍然只放在离线调参脚本里，不写回正式预测默认值。

新增：
- `tools\tune_subscription_prediction.py --mode account-pool-prior`
- 参数：
  - `--account-pool-prior-weights`
  - `--account-pool-prior-recent-samples`
  - `--account-pool-prior-half-lives`

当前做法：
- 对每个待评估样本，只使用其申购日前的历史样本，避免未来函数。
- 从历史 `allocation_fit_json` 读取已获配分桶金额、户数，以及未获配户均申购金额。
- 按目标新股的顶格申购金额截断历史资金需求曲线，得到近期资金池对应的有效申购股数 prior。
- 该 prior 只作为有效申购股数下限：当 `prior * weight` 高于原预测值时才上调，不直接替代倍数模型。

默认候选：
- 权重：`0.8,1.0,1.1,1.2`
- 近期样本窗口：`8,12`
- 半衰期：`4` 个样本

默认全历史窗口结果：
- baseline(best params, no prior)：MAE 50.2959 万元，MAPE 8.50%，漏判 0，误判 0。
- best with prior：MAE 48.3562 万元，MAPE 8.09%，漏判 0，误判 0。
- 最优 prior：`weight=1.1`、`recent_samples=8`、`half_life=4`，触发上调样本为 `920220, 920161, 920218, 920206, 920083`。

最近 8 个历史样本窗口结果：
- baseline(best params, no prior)：MAE 55.1544 万元，MAPE 9.52%，漏判 1（`920206`），误判 0。
- `weight=1.0` 时只触发 `920206`，已消除漏判，MAE/MAPE 与 baseline 持平。
- 当前排序最优为 `weight=1.2`，MAE 53.8436 万元，MAPE 8.64%，漏判 0，误判 0，但触发样本扩至 20 个，后续不宜直接写默认值。

新增验证：

- `python tests\validate_subscription_prediction_tuning.py`
- `python tools\tune_subscription_prediction.py --mode account-pool-prior --top-n 8`
- `python tools\tune_subscription_prediction.py --mode account-pool-prior --max-history-samples 8 --top-n 8`

结论：
- “近期获配分布推资金池下限”的方向有效，特别适合补最近短窗口下的强标签漏判。
- 更稳妥的下一步不是立刻采用 `weight=1.2`，而是把 `weight=1.0/1.1` 放进稳健性矩阵，观察不同 `min_history` 与窗口下的触发样本是否集中在强标签附近。

## 十二、继续推进：prior guard 参数搜索

为了降低 `weight=1.2` 的过度触发风险，本轮继续给离线 prior 增加两个 guard，只用于调参脚本观察，仍不写回正式预测默认值。

新增参数：

- `subscription_prediction_account_pool_prior_min_uplift_ratio`
  - prior 下限相对 base 预测的最小上调比例。
  - 例如 `1.05` 表示 prior 至少比 base 高 5% 才允许触发。
- `subscription_prediction_account_pool_prior_min_source_samples`
  - 资金池 prior 至少需要多少个历史来源样本。
  - 本轮重点观察 `8`，避免早期样本过少时形成噪声。

命令行同步新增：

- `--account-pool-prior-min-uplift-ratios`
- `--account-pool-prior-min-source-samples`
- `--robust-account-pool-prior-min-uplift-ratio`
- `--robust-account-pool-prior-min-source-samples`

同时，`account-pool-prior` 输出新增 `minimal-trigger with prior`：

- 该候选排序先清除漏判/误判，再优先选择 prior 触发样本最少的组合。
- 目的不是替代 MAPE 排名，而是给“强标签保护项”提供更保守的候选视角。

真实样本搜索命令：

- `python tools\tune_subscription_prediction.py --mode account-pool-prior --account-pool-prior-weights 1.0,1.1,1.2 --account-pool-prior-min-uplift-ratios 0,1.03,1.05,1.08,1.10 --account-pool-prior-min-source-samples 1,5,8 --top-n 5`
- `python tools\tune_subscription_prediction.py --mode account-pool-prior --max-history-samples 8 --account-pool-prior-weights 1.0,1.1,1.2 --account-pool-prior-min-uplift-ratios 0,1.03,1.05,1.08,1.10 --account-pool-prior-min-source-samples 1,5,8 --top-n 5`
- `python tools\tune_subscription_prediction.py --mode robustness --top-n 8 --robust-account-pool-prior-min-uplift-ratio 1.05 --robust-account-pool-prior-min-source-samples 8`

搜索结果：

- 全历史窗口：
  - metric best：`weight=1.2,recent_samples=8,half_life=4,min_uplift_ratio=1.08/1.10,min_source_samples=1/5/8`
  - MAE 47.2700 万元，MAPE 7.54%，漏判 0，误判 0，触发 5 个样本：`920220, 920161, 920218, 920206, 920083`
  - minimal-trigger：触发 0 个样本，等同 best params 无 prior，因为全历史窗口本身已无漏判。
- 最近 8 个历史样本窗口：
  - metric best：`weight=1.2,min_uplift_ratio=1.05,min_source_samples=5/8`
  - MAE 51.0139 万元，MAPE 8.15%，漏判 0，误判 0，但仍触发 12 个样本。
  - minimal-trigger：`weight=1.0,recent_samples=8,half_life=4,min_uplift_ratio=0,min_source_samples=1`
  - 只触发 `920206`，消除漏判，MAE/MAPE 与 best params 无 prior 持平。
- 在 `min_uplift_ratio=1.05,min_source_samples=8` 的 robustness 下：
  - `weight=1.0` 在最近 8 窗口稳定只触发 `920206`。
  - `weight=1.1` 多数窗口触发 1-4 个样本，属于可继续观察的折中项。
  - `weight=1.2` 仍常触发 10-12 个样本，虽然指标更好但触发范围偏宽。

本轮结论：

- 如果目标是“强标签安全保护”，当前更稳的是 `weight=1.0`，先作为短窗口保护候选继续观察。

  - 新增 `scan_errors`，扫描阶段失败不再塞进逐只股票 `errors`。

- `tools\add_new_ipo_intraday_cache.py`
  - 如果是扫描阶段失败，汇总改为输出“本次扫描未完成，未进入逐只新股缓存。”
  - 不再打印空代码的失败条目。
- `tests\validate_intraday_cache_tool.py`
