## 九、继续推进：大户资金池参考

用户提出新的建模方向：近期获配情况可以用来估计打新市场上资金体量在某个金额以上的大户约有多少户；这类大户群体相对稳定，不会轻易大幅波动，通常应平滑渐变。

本轮先把这个方向做成观察入口，暂不并入正式预测模型。

新增：

- `tools\tune_subscription_prediction.py --mode account-pool`
- 参数：
  - `--account-pool-thresholds`
  - `--account-pool-recent-samples`
  - `--account-pool-half-life`

当前做法：

- 读取 `allocation_fit_json` 中的获配分桶。
- 对每个申购金额阈值，累计阈值以上分桶的账户数。
- 用 `allocation_fit_confidence` 与样本半衰期做平滑加权。
- `top_apply_below_guaranteed=true` 样本标为时间优先下限，因为公告只确认顶格账户抢时间，不能确认所有顶格申购账户总数。

默认命令：

- `python tools\tune_subscription_prediction.py --mode account-pool`

最近 12 个样本默认阈值输出：

- `>=300` 万：平滑约 76931 户，中位数 73447 户
- `>=500` 万：平滑约 58568 户，中位数 58838 户
- `>=800` 万：平滑约 43250 户，中位数 46264 户
- `>=1000` 万：平滑约 34784 户，中位数 38946 户
- `>=1500` 万：平滑约 7547 户，中位数 0 户
- `>=2000` 万：平滑约 2600 户，中位数 0 户

注意：

- 这些数字不是公告直接披露的真实资产账户数，而是由获配分桶和当前 `allocation_fit` 反推的参考值。
- 对较高阈值，最新样本若顶格申购金额低于阈值，会出现最新样本为 0 户，但平滑值仍由更早样本贡献。
- 下一步更适合把这组平滑参考作为“市场资金池先验”，用于约束有效申购倍数或顶格不足正股分类，而不是直接替代当前倍数模型。

## 十、继续推进：大户资金池 prior 离线检查

本轮把上一轮的 `account-pool` 观察入口向模型约束推进了一步，但仍然只放在离线调参脚本里，不写回正式预测默认值。

新增：
- `tools\tune_subscription_prediction.py --mode account-pool-prior`
- 参数：
  - `--account-pool-prior-weights`
  - `--account-pool-prior-recent-samples`
  - `--account-pool-prior-half-lives`

当前做法：
- 对每个待评估样本，只使用其申购日前的历史样本，避免未来函数。
- 从历史 `allocation_fit_json` 读取已获配分桶金额、户数，以及未获配户均申购金额。
- 按目标新股的顶格申购金额截断历史资金需求曲线，得到近期资金池对应的有效申购股数 prior。
- 该 prior 只作为有效申购股数下限：当 `prior * weight` 高于原预测值时才上调，不直接替代倍数模型。

默认候选：
- 权重：`0.8,1.0,1.1,1.2`
- 近期样本窗口：`8,12`
- 半衰期：`4` 个样本

默认全历史窗口结果：
- baseline(best params, no prior)：MAE 50.2959 万元，MAPE 8.50%，漏判 0，误判 0。
- best with prior：MAE 48.3562 万元，MAPE 8.09%，漏判 0，误判 0。
- 最优 prior：`weight=1.1`、`recent_samples=8`、`half_life=4`，触发上调样本为 `920220, 920161, 920218, 920206, 920083`。

最近 8 个历史样本窗口结果：
- baseline(best params, no prior)：MAE 55.1544 万元，MAPE 9.52%，漏判 1（`920206`），误判 0。
- `weight=1.0` 时只触发 `920206`，已消除漏判，MAE/MAPE 与 baseline 持平。
- 当前排序最优为 `weight=1.2`，MAE 53.8436 万元，MAPE 8.64%，漏判 0，误判 0，但触发样本扩至 20 个，后续不宜直接写默认值。
