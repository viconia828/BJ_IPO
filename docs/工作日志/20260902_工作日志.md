# 2026-09-02 工作日志

## 公告 PDF manifest 改为增量对账

- 用户反馈当前 manifest 在目录状态不一致时仍会调用 `_scan()`，重新打开全部 PDF 做完整性检查，未实现真正的增量更新。
- 已确认根因：`LocalPdfManifest.ensure_current()` 在 `directory_mtime_ns` 变化时直接走 `_scan("directory_changed")`。
- 调整目标：目录变化时只枚举目录项的文件名、大小和 mtime；签名不变的条目直接复用，仅对新增或被替换的 PDF 读取头尾，删除文件只从索引移除。缺失/损坏 manifest 或显式强制重建时才允许全量扫描。
- 开始实现增量对账及新增/修改/删除/强制重建回归测试；保留工作区中本轮刷新产生的离线数据变更。
- 已实现 `_list_pdf_signatures()` 与 `_reconcile()`：目录状态变化时通过 `os.scandir()` 读取目录项元数据，签名相同的 manifest 条目原样复用；只对新增或 size/mtime 变化的 PDF 调用头尾完整性检查。
- manifest 摘要新增 `added_count`、`changed_count`、`removed_count`、`reused_count`、`pdf_opened_count` 和 `incremental_update_count`，统一刷新入口会明确打印本轮增量对账数量。
- 删除和重命名通过文件名差集更新；若目录枚举临时失败，保留现有 manifest 并返回 `cache_stale`，不会误清空索引。原有官网下载后单文件 `register_pdf_file()` 快路径保持不变。
- 扩充 `validate_local_pdf_manifest.py`：5 份初始 PDF 后新增 1 份时断言 `added=1 / reused=5 / pdf_opened=1 / full_scan_count=1`；替换 1 份只打开 1 份；删除 1 份打开 0 份；只有显式 `force=True` 才把全量扫描计数增至 2。
