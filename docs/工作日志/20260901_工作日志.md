## 公告 PDF manifest 增量索引

- 用户确认随着本地样本增加，刷新新股数据时不应再反复全量扫描招股说明书等本地文件，需要新增独立 manifest。
- 已定位重复开销：`bse_ipo_valuation._find_pdf_candidates()` 每次查询都会枚举 `公告文件/*.pdf`，并对全部文件重复做 PDF 头尾完整性检查；replay 与申购 history 会按代码、按文档类型多次调用该入口。
- 方案：建立持久化公告 PDF manifest，缓存文件名、大小、修改时间、代码映射和完整性；目录未变化时按代码直接命中，新增/删除/重命名时重建，原位替换文件时对命中的少量文件做签名复核。
- 已新增 `code/local_pdf_manifest.py`，生产 manifest 写入 `data/offline_tuning/local_pdf_manifest.json`；当前索引 `218` 份完整 PDF、`59` 个代码，不完整文件 `0`，初次全量扫描计数为 `1`。
- `bse_ipo_valuation._find_pdf_candidates()` 已改为从 manifest 按代码取候选文件，保留原有文档别名、排除词、完整性过滤、招股摘要/全文用途优先级和精确文件名优先级。
- 官网下载入口已接入增量登记：新下载或覆盖的 PDF 只更新单文件条目；复用未变化的本地 PDF 不重写 manifest。
- 统一刷新入口会在开始时报告 `cache_hit` 或 `rebuilt`，并把 manifest 摘要写入样本 manifest 的 `sync_summary.local_pdf_manifest`；新增 `--force-rebuild-pdf-manifest` 排障开关。
- 新增 `tests/validate_local_pdf_manifest.py`，覆盖首次构建、目录未变化命中、代码映射、完整/损坏过滤、招股文件选择优先级、下载后增量登记和原位替换复核。
