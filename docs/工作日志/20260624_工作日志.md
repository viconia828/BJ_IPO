# 2026-06-24 工作日志

## 一、问题复盘：手工分档标签 CSV 被 Excel/ANSI 编码阻断

用户修改 `data\offline_tuning\subscription_ladder_labels.csv` 后，启动申购资金自动调参时报错：

- `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb3 ...`
- 报错发生在 `code\subscription_ladder_labels.py` 的 `load_label_rows()`，尚未进入标签行同步和空列补齐逻辑。

排查后确认：

- 这次不是普通空值导致的错误。
- 手工分档 CSV 被保存成了 `GB18030/CP936` 一类 Excel 常见中文编码，旧逻辑只按 `utf-8-sig` 读取，因此直接解码失败。
- 原有 `sync_label_rows()` 已经会用历史样本补齐 `security_name_abbr`、`apply_date`、`issue_price`、`online_issue_shares`、`top_apply_amount_wan`，并保留 `manual_ladder`、`manual_note`，但编码错误会让该逻辑无法启动。

## 二、修复：标签 CSV 多编码读取与自动标准化

本轮调整 `code\subscription_ladder_labels.py`：

- 标签 CSV 读取支持依次尝试：
  - `utf-8-sig`
  - `utf-8`
  - `gb18030`
  - `cp936`
- 保留 `load_label_rows()` 对外签名，新增内部读取函数返回来源编码，避免影响既有调用方。
- `sync_label_rows()` 在读取到非 UTF-8 标签文件时，会在同步后统一写回为 `utf-8-sig`。
- 同步时继续保护用户手填列：
  - `manual_ladder`
  - `manual_note`
- 其它自动列继续从申购历史样本补齐或刷新。
- 同步摘要新增：
  - `source_encoding`
  - `encoding_normalized`
  - `label_file_written`
