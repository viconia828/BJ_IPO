- 可变字段：例如价格、PE、市值、抓取时间、来源、状态

### 3. Wind quota 控制与最小化验证已落地

`wind_helper.py` 当前已经具备以下能力：

- 请求前先查本地缓存
- 每次真实 Wind 请求都写入 `request_log.json`
- 统计当日请求次数
- 依据 `wind_daily_request_quota` 控制调用
- 支持按批次取数，避免逐只逐字段零散请求
- 验证时优先走最小链路，不做大范围批量扫描

当前原则已经明确：

1. 先验证“首次补库是否成功”
2. 再验证“重复运行是否命中缓存且不再请求”
3. 不做全量历史回填
4. 不做为了验证而验证的多股票大扫

### 4. 方法一已恢复，但核心改为“Wind 原料字段 -> 本地计算”

在排查 Wind 估值字段时，已经确认以下情况：

- `pe_ttm`、`pb_lf`、`mkt_cap_ard` 这类 Wind 成品估值字段，字段名本身能被识别
- 但当前账号 / 服务口径下，这些字段返回值为空
- 同时 `sec_name`、`close`、`eps_ttm`、`total_shares` 等原料字段可以返回

因此当前策略已切换为：

1. 优先取 Wind 原料字段
2. 本地计算 `PE = close / eps_ttm`
