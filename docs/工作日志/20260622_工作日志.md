# 2026-06-22 工作日志

## 一、问题复盘：920136 报东方财富 SSL 失败

用户运行 `运行.bat` 输入 `920136` 后，程序在约 60 秒后报错：

- `数据获取失败：东方财富请求失败: [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol`

排查后确认：

- 主流程 `build_analysis_data()` 会先执行 `ipo_data_helper.prepare_ipo_data()`，再进入北交所公告下载与 PDF 解析。
- 当前默认 IPO 数据源为 Tushare，但 Tushare 路径仍会用东方财富做目标 IPO 字段补充。
- 当 Tushare 未形成可用目标 IPO 数据、东方财富补充又发生网络/SSL 异常时，旧逻辑会直接把东方财富异常抛出，导致流程尚未进入北交所公告下载阶段。
- 本地 `公告文件` 中没有 `920136` 的 PDF，按业务预期应当继续尝试北交所公开发行一览和公告/PDF 补字段。

## 二、修复：Tushare + 东方财富失败时优先转北交所/PDF

本轮调整 `code\tushare_ipo_helper.py`：

- 在 IPO summary 中新增：
  - `bse_newshare_fallback_used`
  - `pdf_target_fallback_pending`
  - `fallback_errors`
- 新增 `_build_bse_or_pdf_pending_bundle()`：
  - 先尝试北交所公开发行一览 `build_newshare_ipo_info_by_post_listing_code()`。
  - 若公开发行一览成功，目标 IPO 来源标记为 `bse_newshare`。
  - 若公开发行一览也失败，返回最小目标信息：
    - `SECURITY_CODE`
    - `SECURITY_NAME_ABBR`
    - `source = bse_pdf_pending`
  - 让主流程继续进入北交所公告下载与 PDF 解析阶段，由招股说明书、发行公告、发行结果公告继续补核心字段。
- 新增 `_build_eastmoney_bundle_with_bse_fallback()`：
  - 缺 Tushare token 或其他必须回退东方财富的场景下，如果东方财富目标数据失败，不再直接中断，而是转北交所/PDF fallback。
  - 若东方财富目标数据成功但近期样本失败，则保留目标数据，近期样本置空并记录错误，不再丢弃目标 IPO 信息。
- Tushare 路径中，东方财富补充失败会写入 `fallback_errors`，后续排查可看到具体失败来源。

## 三、报告来源文案同步

本轮调整 `code\report_source_helper.py`：

- `target_source = bse_newshare` 时，报告数据来源显示为北交所公开发行一览。
- `target_source = bse_pdf_pending` 时，报告数据来源显示为北交所公告/PDF 补字段。
- Tushare 主路径下如发生北交所回退，会与东方财富补充分开展示，避免把所有目标股回退都笼统写成东方财富。

## 五、当前结论

`920136` 这类目标股在 Tushare 与东方财富网络均不稳定时，后续不应再卡死在东方财富 SSL 错误上；程序会先尝试北交所公开发行一览，必要时进入 PDF pending，让主流程继续下载并解析北交所公告。

后续可观察：

- 若 `bse_pdf_pending` 场景下本地/官网仍拿不到招股说明书，主流程会按原有 `RequiredProspectusNotFoundError` 明确报缺公告，而不是误报东方财富失败。
- 若近期样本也因东方财富或 Tushare 网络失败为空，报告的方法二样本可能减少或不可用；这是数据可得性问题，已通过 `fallback_errors` 留痕。
