## 申购规模自动调参运行内缓存

用户反馈申购规模自动调参单次运行很慢，并要求先落设计方案再动代码。

排查结论：

- 小规模 10 候选剖面在改造前耗时约 239 秒。
- 时间几乎全部花在 account-pool 碎股门槛估算：`_estimate_account_pool_fractional_cutoff()` 约 238.7 秒，`_estimate_account_pool_accounts_ge()` 约 234.8 秒。
- 已有的是离线样本/阈值文件缓存；缺的是单次调参运行内的派生索引缓存，所以每个候选、每个样本都会重复解析阈值列、排序历史行和扫描插值点。

本轮设计：

- 新增 `docs/设计文档/07_申购调参运行内派生缓存方案.md`。
- 缓存只驻留在本次运行的参数字典中，不跨进程、不写新数据文件。
- 不缓存最终 `build_subscription_prediction()` 结果，只缓存 account-pool rows、阈值索引、排序后的历史行、每行可用插值点，以及 `_estimate_account_pool_accounts_ge()` 的查询 memo。

本轮实现：

- 在 `code/subscription_predictor.py` 中新增 account-pool runtime cache/index，`_estimate_account_pool_fractional_cutoff()` 改为复用索引。
- 在 `tools/tune_subscription_prediction.py` 中，调参入口和搜索/鲁棒性/prior 分支会预加载 account-pool rows，并在输出中只暴露轻量摘要，避免把 rows/index 写进报告 JSON。
- 在 `tests/validate_subscription_predictor.py` 中新增运行内索引复用回归，确认同一 params 下第二次预测复用同一 index 和 memo。

验证：

- `python -X utf8 -m py_compile code\subscription_predictor.py tools\tune_subscription_prediction.py tests\validate_subscription_predictor.py tests\validate_subscription_prediction_tuning.py`
- `python -X utf8 tests\validate_subscription_predictor.py`
- `python -X utf8 tests\validate_subscription_prediction_tuning.py`
- `python -X utf8 tools\tune_subscription_prediction.py --mode search --max-candidates 3 --top-n 1 --no-auto-refresh-history --no-auto-refresh-dataset --no-download-missing-announcements --json`

性能结果：

- 同样 10 候选剖面改造后耗时约 0.294 秒。
- `_load_account_pool_rows()` 从候选热路径中的重复读取降为本轮剖面的 1 次。
- `_account_pool_thresholds()` 为 1 次。
- `_estimate_account_pool_accounts_ge()` 仍被调用约 23037 次，但索引+memo 后合计约 0.077 秒。
## 920176 顶格不足正股时的碎股边界修正

用户指出：即使正股门槛高于顶格，碎股分配也不应直接判定为顶格全员抢时间，而应按网上发行手数从分户曲线向下数出碎股边界。

排查结论：

- 920176 发行公告字段为：网上发行 `794.70` 万股，即 `79470` 手；顶格申购 `39.73` 万股，对应 `880.4168` 万元。
- 当前有效申购规模估算使正股门槛为 `982.3528` 万元，确实高于顶格，因此“正股不可达”成立。
- 旧逻辑在 `max_full_lots <= 0` 时直接退出 account-pool cutoff，并回退为 `top_apply_below_guaranteed_all_time_priority`，把碎股门槛错误地放到了顶格。

本轮修复：

- `_estimate_account_pool_fractional_cutoff()` 允许 `max_full_lots = 0`，此时 `full_allocated_lots_estimate = 0`，`leftover_lots = online_issue_shares / 100`。
- 无公告分档时，无论正股门槛是否高于顶格，先尝试 account-pool cutoff；只有 cutoff 算不出来才回退为顶格全员抢时间。
- `top_apply_time_priority_required` 不再简单等于 `top_apply_below_guaranteed`；若 account-pool cutoff 低于顶格，则顶格档预计可获碎股，抢时间只可能发生在碎股边界。

验证结果：

- 920176 当前重放：碎股边界约 `638.87` 万元，`leftover_lots = 79470`，`full_allocated_lots_estimate = 0`。
- 顶格抢时间提示变为：`否（顶格不足正股，但顶格档预计可获碎股）`。
