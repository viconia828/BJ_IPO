# 北交所新股估值项目工作日志

日期：2026-05-06
记录人：Codex
目标：定位并修正 `920200` 报告生成耗时过长的问题，优化招股书解析和 Edge PDF 导出流程，并补交新增首日分时走势文件。

## 一、问题定位

本次从 `运行.bat` 输入 `920200` 后长时间无法完成报告生成的问题入手，重点排查了两个阶段：

- 数据准备阶段：主要耗时来自招股说明书 PDF 解析，尤其是可比公司、业务描述和老股数相关信息提取。
- PDF 导出阶段：Edge 实际已经能够生成 PDF，但在部分情况下进程退出或临时 profile 清理较慢，容易让程序等待过久，甚至出现“PDF 已生成但流程仍被判定失败”的现象。

排查确认后，没有增加 Word、浏览器外工具或其他 PDF 兜底方案，仍保留原来的 Edge 打印 PDF 路径。

## 二、今日完成事项

- 为 `code/pdf_parser.py` 增加 PDF 解析结果缓存，缓存内容包括老股数解析结果、可比公司列表和主营业务描述。
- 缓存按 PDF 路径、文件大小和修改时间校验，源 PDF 变化后会自动失效并重新解析。
- 将解析缓存目录 `data/pdf_parse_cache/` 加入 `.gitignore`，避免本地缓存进入版本库。
- 调整 `code/report_generator.py` 的 Edge 启动参数，使用新版 headless 模式，并关闭后台模式、扩展、后台网络和 Startup Boost 相关能力。
- PDF 导出逻辑改为检测目标 PDF 是否已经完整写入并稳定，再停止本次启动的 Edge 进程并返回成功。
- Edge 日志改写入临时日志文件，避免大量 stdout/stderr 输出阻塞进程。
- 临时 profile 清理失败不再影响已经成功生成的 PDF 报告。
- 新增首日分时走势缓存文件纳入版本管理：`首日分时走势/920186.csv`。

## 三、920200 验证结果

本次优化后，`920200` 数据准备阶段已经从此前的大 PDF 扫描耗时降到约 6 秒。

实际运行 `python .\code\bse_ipo_valuation.py 920200` 验证：

- PDF 生成成功。
- 完整流程耗时约 56.5 秒。
- 最新生成文件为 `输出/920200_振宏股份_估值_20260506_165442.pdf`。
- 生成 PDF 大小约 346 KB，检测到 `%%EOF` 结尾，共 3 页。

当前剩余主要耗时来自 Edge 自身的 PDF 打印过程，数据解析阶段已经明显缩短。

## 五、当前建议

日常继续通过 `运行.bat` 生成报告即可。`输出/` 目录中的 PDF、HTML 和 `_report_pdf_*`、`_edge_probe_*` 等目录均属于生成结果或诊断临时文件，不影响程序运行，可按需清理。

`data/pdf_parse_cache/` 是本次新增的本地解析缓存目录，建议保留；后续再次生成同一只新股报告时可以减少重复解析招股书的时间。
